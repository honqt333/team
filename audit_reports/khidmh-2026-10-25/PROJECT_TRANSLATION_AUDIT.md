## 2. التصحيح الأهم: خطأ القياس

### 2.1 ما يُبلَّغ

`php artisan translations:check` يُبلّغ **713 مفتاحاً ناقصاً** لكل لغة. اختبار `I18nCoverageTest` يسمح بـ **708**. النتيجة: **اختباران فاشلان** (AUD-015)، وأساس الاختبار رُفع **خمس مرات** موثّقة في تعليقات الملف:

```
0  →  94  →  700  →  708  →  (الحالي 713)
     "Vue i18n migration ... added ~94 system.* keys to resources/js/i18n/lang/*.json
      but the lang/{ar,en}/*.php backend files have not been updated to match"
```

التعليق نفسه يشرح — لكن التفسير **غير دقيق**: المفاتيح موجودة في JSON كما سأثبت أدناه.

### 2.2 السبب الجذري

`app/Console/Commands/TranslationsCheck.php`:

```php
// الأسطر 95-106 — يُبنى وينمو…
$vueDefined = [];          // locale => ['key.sub' => true]
foreach ($locales as $locale) {
    $vueDefined[$locale] = [];
    $jsonPath = $basePath."/resources/js/i18n/lang/{$locale}.json";
    if (file_exists($jsonPath)) {
        $arr = json_decode(file_get_contents($jsonPath), true) ?: [];
        foreach ($this->flatten($arr) as $k => $_) {
            $vueDefined[$locale][$k] = true;    // ← يُجمع…
        }
    }
}

// السطر 188 — يُستعمل…
foreach ($usages as $key => $files) {
    if (! isset($definedKeys[$locale][$key])) {   // ← $definedKeys = ملفات PHP فقط!
        $missing[$locale][$key] = $files;
    }
}
```

**`$vueDefined` لا يُستعمل أبداً في تحديد النقص.** يُستعمل فقط في السطر 199 — لفحص تطابق ar/en بين ملفَّي JSON.

**النتيجة**: كل مفتاح يستهلكه Vue عبر `$t()` **يُبلَّغ ناقصاً**، حتى لو كان موجوداً في `ar.json`/`en.json`.

### 2.3 إثبات (1) — مفتاح مبَلَّغ ناقص وهو موجود فعلاً

```bash
$ php artisan translations:check --locale=ar | grep admin_users.search_placeholder
    system.admin_users.search_placeholder  (resources/js/Pages/System/AdminUsers/Index.vue)

$ grep -n "search_placeholder" resources/js/i18n/lang/ar.json
1395:      "search_placeholder": "ابحث بالاسم أو البريد...",
```

وفي وقت التشغيل:
```json
$ python3 -c "import json; d=json.load(open('resources/js/i18n/lang/ar.json')); \
    print(d['system']['admin_users']['search_placeholder'])"
ابحث بالاسم أو البريد...
```
⇒ **المفتاح يُحلّ بشكل صحيح**. إضافته عبر `--vue` لا يغيّر النتيجة (713) — لأن الخلل ليس في خيار بل في منطق المقارنة.

### 2.4 إثبات (2) — التمييز الكمي

```python
reported missing      : 713
FALSE POSITIVES (موجود في JSON، مترجم فعلاً) : 700
GENUINELY missing (غائب عن PHP lang AND Vue JSON) : 13
```

**الخلاصة**: نسبة النقص الحقيقية = **13 من 713 (1.8%)**.

### 2.5 الأثر

| الأثر | التفصيل |
|---|---|
| **بوابة جودة بلا قيمة** | `I18nCoverageTest` تراقب رقماً لا يعكس الواقع — أي انحدار حقيقي *يُطمس* بين 700 إيجابية كاذبة |
| **قرارات مبنية على رقم مضلّل** | الرقم 708 مُوثَّق كـ "مقبول" — أي شخص سيقرأه يظن أن 708 مفتاحاً مفقوداً |
| **إغفال 13 مفتاحاً حقيقياً** | 6 منها رسائل خطأ دفع تظهر للمستخدم |
| **خطر إصلاح مخطئ** | من ينظّف "النقص" سيضيف 700 مفتاحاً مكرراً إلى `lang/*.php` — تضخيم بلا فائدة |

### 2.6 الحل

| التغيير | التفصيل |
|---|---|
| **1** | عند بناء `$missing`، اعتبر المفتاح موجوداً إذا وُجد في `$definedKeys[$locale]` **أو** `$vueDefined[$locale]` |
| **2** | أضف خيار `--source=php\|vue\|both` (افتراضي `both`) للتمييز الصريح |
| **3** | أعد ضبط `MISSING_KEYS_EXPECTED` إلى القيمة الحقيقية (≈13) |
| **4** | أضف اختبار انحدار: مفتاح في JSON فقط ⇒ لا يُبلَّغ ناقصاً |

**معايير القبول**: الأداة تُبلّغ ≤20؛ `I18nCoverageTest` أخضر؛ 0 مفاتيح JSON مُبلَّغة ناقصة.

## 6. مشكلات RTL / LTR

> **ملاحظة منهجية**: كل ما يلي **تحليل ساكن** (قراءة الكود). **لم يُجرَ فحص بصري** بالمتصفح — انظر §8.

### 6.1 ما هو صحيح

| الممارسة | العدد | الحكم |
|---|---|---|
| `dir="ltr"` على محتوى ثنائي الاتجاه (هواتف، بريد، VIN، مبالغ) | **584** | ✅ **صحيح تماماً** — هذا هو الاستخدام الصحيح |
| `dir="rtl"` صريح | 22 | ✅ |
| `dir="auto"` | 5 | ✅ |
| إجمالي استخدام `dir` | **611** | |

**عيّنة على صحة الاستخدام:**
```vue
<!-- resources/js/Components/Customers/CustomerFormModal.vue:604 -->
<span class="font-mono" dir="ltr">

<!-- resources/js/Pages/Purchasing/Suppliers/Show.vue — 42 استخداماً -->
```

### 6.2 ما يحتاج مراجعة

| الملاحظة | العدد | الأثر | الأولوية |
|---|---|---|---|
| **خصائص اتجاهية فيزيائية** (`ml-`, `mr-`, `pl-`, `pr-`) | ~92 | في RTL تنعكس يدوياً ⇒ أخطاء محاذاة | P2 |
| **خصائص منطقية** (`ms-`, `me-`) | 65 | ✅ الاتجاه الصحيح | — |
| **نصوص مختلطة عربي/إنجليزي** في حقول الإدخال | يحتاج فحص بصري | قد تنعكس | P3 |
| **`text-left` / `text-right` الصريحة** | يحتاج قياس | قد تتعارض مع RTL | P3 |

**التوصية**: تحويل تدريجي من `ml-`→`ms-`، `mr-`→`me-`، `pl-`→`ps-`، `pr-`→`pe-`.
Tailwind 3.2+ يدعم هذه الخصائص. **لا داعي للتحويل العاجل** — خصائص `ml/mr` تعمل في RTL لكن بنفس اتجاه `margin-left` الفيزيائي (أخطأ perceptually).

### 6.3 فحص حالة الخط (RTL)

**ممتاز** — هذا يعالج مشكلة عرض الأرقام في الواجهة العربية.

### 6.7 حالات الجمع وصيغ الرسائل

**تحذير**: PHP `trans_choice` لم يُستخدم بشكل ملحوظ. معظم الرسائل نص ثابت ⇒ **لا دعم للجمع العربي**.

| الرسالة | الحالية | المشكلة |
|---|---|---|
| "تم رفع N ملف" | نص ثابت | لا تصريف للعدد |
| "N عنصر في السلة" | نص ثابت | ❌ |

**التوصية**: استخدام `trans_choice` / صيغة ICU للرسائل التي تحتوي عدّاداً. **الأولوية P3** (عدد قليل من الرسائل).

### 6.8 قصّ النصوص وتداخلها

| المصدر | الأداة | الحالة |
|---|---|---|
| الحقول | `truncate` CSS | يحتاج فحص بصري |
| الجداول | `max-w-*` + `truncate` | متفرق |
| القوائم | — | **فحص بصري مطلوب** |

### 6.9 RTL في القوائم والجداول

- **القوائم**: التخطيط معكوس تلقائياً في RTL (خاصية `direction` ترث) ✅
- **الجداول**: `text-align: start` ✅ في الأعمدة الجديدة (لكن `text-left` موجودة في القديم)
- **ترتيب الأعمدة**: معكوس تلقائياً ✅

## 7. المفاتيح غير المستخدمة

### 7.1 فحوصات القابلية للاكتشاف

| الفحص | النتيجة |
|---|---|
| `lang/*.php` مقابل استخدام `__()` / `trans()` | **تم فحصه** — 13 مفتاحاً ناقصاً (مستخدمة لكن غير معرَّفة) |
| `ar.json` / `en.json` مقابل `$t()` | **تم فحصه** — نفس النتيجة |
| مفاتيح **معرَّفة وغير مستخدمة** | ⚠️ **لم يُفحص بشكل شامل** — أداة `translations:check` لا تُبلّغ عن ذلك |

### 7.2 نقطةaje

الأداة الحالية تُبلّغ عن:
- ✅ ناقص (مع خلل في دقتها)
- ❌ **غير مستخدم** — غير مُبلَّغ عنه

**التوصية**: إضافة تقرير "unused keys" إلى الأداة (اختياري). **الأولوية P3** — المفاتيح الزائدة لا تكسر شيئاً، لكنها تضخّم الملفات.

### 7.3 مفاتيح مكرّرة

**لم يُرصد تكرار** بين `lang/*.php` و JSON — المجموعتان منفصلتان بالأسماء (`common.*` موجود في **كلتيهما** —Overlap مقصود).

> **ملاحظة**: `common.*` موجود في PHP و JSON معاً. هذا overlap مشروع (نفس المفاتيح، مصدران) لكنه سبب إضافي لالتباس أداة الفحص.

## 9. توحيد المصطلحات

### 9.1 الحالة

بما أن الترجمة **متكاملة**, المشكلة ليست في **غياب** المصطلحات بل في **تعدد المرادفات** المحتملة. الفحص الآلي لـ "المصطلح الواحد بأكثر من ترجمة" لم يُنفَّذ بعد.

**المستوى** — عدد قليل من التطابقات المرصودة يدوياً:
| عربي | إنجليزي | ملاحظة |
|---|---|---|
| مركز / فرع | center / branch | **مترادفان في النظام!** — `Center` يُسمّى "مركز" في بعض السياقات و"فرع" في أخرى (مثال: `hr.employees.branch` لعنوان `Center`) |
| أمر العمل / كرت الصيانة | work order | النظام يستخدم **"كرت الصيانة"** في العربية User-facing (MSG). Backend = `WorkOrder` |
| عرض السعر | quote | متّسق |
| فاتورة | invoice | متّسق |
| قطعة / قطعة غيار | part | يحتاج تثبيت |

### 9.2 توصية

| الخطوة | التفاصيل |
|---|---|
| **1** | استخراج **قاموس مصطلحات** في `docs/GLOSSARY.md` (عربي ↔ إنجليزي ↔ الرمز البرمجي) |
| **2** | تثبيت كل مسمّى، **بما فيه center/branch** — ثم تطبيقه على `lang/` |
| **3** | **لا تغيّر** المصطلحات القائمة دون مراجعة الأثر (المستخدم اعتاد عليها) — الهدف **توحيد** لا **تغيير** |
| **4** | اختبار انحدار يضمن ثبات المصطلحات |

> **تحذير مهم**: تغيير مصطلح ظاهر للمستخدم (مثل "فرع" → "مركز") **قد يُربك** من اعتاد اللغة الحالية. **قرار تجاري مطلوب** — ولا يجب تنفيذه ضمن إصلاح تقني.
