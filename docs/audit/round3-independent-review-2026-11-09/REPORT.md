# مراجعة الجولة الثالثة — إصلاحات المدفوعات والطباعة

القرار: قبول جزئي. لم يعدل المراجع كود التطبيق أو بيانات العمل. نتائج الفحص تخص الملفات الحالية، ولا تنسب اختلافات الأرقام إلى وكيل معين.

## P1 — معالج العربية يلغي حماية تهريب HTML

app/Support/ArabicPdfShaper.php::shapeText يفك HTML entities ثم shapeHtml يعيد النص إلى HTML دون تهريبه. أثبت اختبار محلي أن:
`<p>وصف &lt;img src=&quot;https://example.invalid/review.png&quot;&gt;</p>`
يتحول إلى عنصر img فعلي. الاختبار لا يجري اتصالاً خارجياً.

app/Services/Print/PrintService.php:128 و:163 يفعّلان isRemoteEnabled قبل تحميل HTML المعالج. لذلك يستطيع نص مستخدم مهروب داخل قالب PDF أن يصبح محتوى HTML فعالاً؛ قد يؤدي ذلك إلى طلب موارد خارجية أو داخلية بحسب قيود المحرك وبيئة التشغيل. لم تُختبر شبكة داخلية أو قراءة ملفات، فلا نعد ذلك استغلال SSRF مكتمل الإثبات.

المطلوب: الحفاظ على النص كنص، وتهريب ناتج تشكيل العقد النصية بعد فك الكيانات ومعالجتها، أو معالجة DOM آمنة تحفظ فصل النصوص عن الوسوم. إضافة اختبارات تمنع تحويل img/style وأي علامات مهربة إلى عناصر، مع نص عربي مختلط وأرقام وكيانات. لا تُغلق المسألة بتحسين اختبارات الشكل فقط.

## K05 — مسار فواتير الاشتراك لا يمر بالمعالج

app/Services/Invoice/SubscriptionInvoiceService.php:134 ما زال يستعمل loadView مباشرة، بينما ربط ArabicPdfShaper موجود في PrintService فقط. توحيد الخط حدث فعلاً، لكن معالجة تشكيله غير شاملة لمسارات PDF التي شملتها الملاحظة الأصلية. المطلوب التحقق من فاتورة اشتراك مولدة من الخدمة نفسها بعد معالجة مشكلة التهريب، ثم معاينتها بصرياً.

عاين المراجع صورة الاختبار المتاحة /tmp/test-invoice-arabic-pdf-shaper.pdf.png: العناوين والوصف العربي يظهران متصلين في هذه العينة. هذا دليل بصري محدود للصورة نفسها؛ لا يثبت أنها ناتج مسار فاتورة الاشتراك أو أن كل التخطيطات والأرقام سليمة.

## ما تأكد إصلاحه

- حذف دفعة المشتريات يمر الآن بقفل فاتورتها وإعادة احتساب الرصيد، والاختبارات تغطي الحذف الكامل والجزئي والحذف المباشر عبر Eloquent.
- تقرير العملاء يستخدم PrintEngine بنوع customers_report، مع تسجيل TemplateCustomersReport؛ الملاحظة المعمارية السابقة عولجت في المصدر.
- سقف العربية725، أدنى من733؛ نجح الحارس الحالي. هذا تقدم ومنع تراجع، وليس ادعاء الوصول إلى صفر نصوص ثابتة على مستوى النظام.

## الاختبارات والأدلة

شغلت الملفات الأربعة المحددة في الملخص: PurchasePaymentSafetyTest وArabicPdfShapingTest وHardcodedArabicTest وFinancialSafetyAuditAcceptanceTest. النتيجة الفعلية28 اختباراً و88 تأكيداً ناجحاً، وليست32 و107 في هذه اللقطة. اختبار التهريب المستقل نجح بتأكيدين لإثبات السلوك الخاطئ؛ ليس اختبار قبول. انسخ ArabicShaperSecurityReviewTest.php إلى /tmp وشغله عبر vendor/bin/phpunit --configuration phpunit.xml.

اختبارات SQLite لا تثبت تزامن أقفال MySQL. لم يُشغّل PHPStan مستقلاً في هذه الجولة. لا تغلق هذه الحزمة تلقائياً الملاحظات المالية الأخرى التي لا تغطيها اختباراتها.

بناء npm run build وتنظيف php artisan optimize:clear نجحا، وسجلاهما مرفقان.
