# الدفعة الثانية — سلامة المستندات والفترات الموحدة

الحالة: تنفيذ محلي، دون نشر أو تغيير سجلات قاعدة العمل. لم تُنشأ مهاجرة لأن الإصلاح لا يغير المخطط ولا يحذف أو يعيد تصنيف البيانات السابقة.

## الإصلاحات

- إصدار الفاتورة يعيد قراءتها بقفل صف داخل معاملة، ثم يفحص draft قبل استهلاك التسلسل. النسخة القديمة لا تستطيع تغيير الرقم أو استهلاك تسلسل ثانٍ. أضيف logActivity للإصدار ورسالة رفض مترجمة.
- حذف بند الراتب يجلب البند من علاقة المسير المحدد، ويقفل المسير ويعيد فحص حالته وتفويضه. رفض رابط أب/ابن غير متطابق، وحماية المسير المدفوع، مع تسجيل الحذف المشروع.
- الفترة الجديدة موحدة على مستوى المستأجر الذي يمثل كياناً ذا تسجيل ضريبي واحد: center_id فارغ للفترة، وفرع كل معاملة محفوظ للتفصيل الداخلي. تبديل الفرع الحالي لا يغير معاملات الفترة أو مصفوفة الفترات.
- عرض هذه البيانات المركزية يتطلب COMPANY_MANAGE إضافة إلى صلاحية الفواتير المناسبة. الإنشاء والاعتماد وإعادة الفحص تتطلبان الصلاحيتين أيضاً؛ صلاحية فرع للفواتير وحدها لا تكشف بيانات جميع الفروع. لم تُضف صلاحية موازية خارج السجل المعتمد.
- تجميع المستندات يستبعد المسودات والملغاة والمحذوفة؛ الإشعار الدائن يعالج بقيم سالبة وفق enum الحقيقي. تحفظ مبالغ المصادر الأصلية بدلاً من قبول مبالغ المتصفح؛ لا يقبل الطلب معاملات مجهولة أو مكررة. يعاد فحص أهلية المعاملات المختارة عند الاعتماد لمنع إدراج المعاملة المرحلة في إقرار آخر.
- قفل سجل المستأجر ينسق إنشاء واعتماد وإعادة فحص الفترات، بما في ذلك حال عدم وجود سجل فترة سابق. إعادة فحص نسخة قديمة لا تعدل فترة اعتمدت بالفعل.
- تظهر ملاحظة عربية وإنجليزية في صفحات الفترات توضح أن النطاق يشمل كل الفروع.

## التوافق والبيانات السابقة

لا تحذف عملية إنشاء جديدة أي فترة قائمة. وجود فترة لنفس المفتاح يرفض الإنشاء ويوجه لفتح الحالية. فترات الفروع السابقة محفوظة للعرض والتصدير الداخلي، لكن يمنع اعتمادها أو إعادة بنائها أو تصديرها كإقرار موحد؛ تتطلب تسوية موثقة قبل اعتماد إقرار يجمع الفروع. هذا يحافظ على الأثر السابق بدلاً من دمج مستندات مالية تاريخية تلقائياً. لا يتضمن هذا التغيير أداة تسوية آلية لهذه السجلات.

تجميع المستأجر يفترض تسجيلاً ضريبياً واحداً كما هو نموذج الإعداد الحالي. لا يضيف دعماً لعدة كيانات قانونية مستقلة داخل مستأجر واحد، ولا ينبغي استخدامها تحت إقرار واحد. التقارير التفصيلية للفروع تبقى للتشغيل والمراجعة.

الفترات المتاحة حالياً ربع سنوية كما في النظام القائم؛ الدفعة لا تضيف دعماً للفترات الشهرية ولا تعني اكتمال نموذج الإقرار لكل أنواع التعاملات الضريبية. مصنف الإقرار الرسمي وتكامل الإرسال موضوع منفصل.

## التحقق

- مجموعة الخلفية: **33 اختباراً ناجحاً / 242 تأكيداً**. الملفات: SecondBatchFinancialSafetyTest، TaxPeriodsReportTest، InvoicingSecurityTest، InvoiceServiceTest، PaymentConcurrencySafetyTest. تتضمن حالات النسخ القديمة، فرعين ومستأجر آخر، قيم متصفح مزورة، إشعار دائن ومسودات وحذف، صلاحيات مركزية، حفظ التاريخ، منع تكرار المعاملات، والحذف المشروع وغير المشروع لبند الراتب.
- اختبار MySQL في قاعدة عشوائية مستقلة: عمليتان مستقلتان تحملان مسودة الفاتورة نفسها قبل الانطلاق المتزامن؛ قُبلت واحدة ورُفضت الأخرى وبقي التسلسل 1. ثم طلبا إنشاء لنفس فترة التسجيل: قُبل واحد ورُفض الآخر، وبقي سجل واحد. حُذفت قاعدة الاختبار في نهاية التجربة. لم يستعمل الاختبار قاعدة العمل لحفظ بياناته.
- اختبار MySQL هذا يثبت سباقي الإصدار وإنشاء الفترة، وليس اختبار ضغط أو إثباتاً لكل تداخل في الرواتب والمخزون.
- بناء الواجهة نجح بعد ملاحظة النطاق الجديدة. تنسيق PHP مستهدف، وتنظيف الكاش ناجح.

الأدلة وبرنامج اختبار MySQL في second-batch-evidence-2026-11-09. برنامج الاختبار يقرأ إعداد الاتصال المحلي دون طباعة الأسرار، وينشئ قاعدة ذات اسم عشوائي خاص به ويحذفها؛ يتطلب صلاحية إنشاء وحذف قواعد اختبار. لا تشغله ببيئة لا تسمح بذلك.
