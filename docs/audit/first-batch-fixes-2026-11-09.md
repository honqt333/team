# إغلاق الدفعة الأولى — 9 نوفمبر 2026

الحالة: إصلاحات محلية جاهزة للمراجعة، دون نشر أو تشغيل مهاجرات على قاعدة العمل ودون نقل أو حذف ملفات العملاء الفعلية.

## التغييرات

- **SEC-01:** دعوات الموظفين تحمل رمزاً عشوائياً مخزناً كبصمة SHA-256 وموعد انتهاء. إعادة الإرسال تلغي السابق. القبول يعيد قراءة المستخدم تحت قفل في معاملة ويستهلك الرمز، ولا يعيد تنشيط حساب معطل. المصادقة الثنائية المؤكدة تمر بتحدي الدخول قبل تسجيل المستخدم. حقول الدعوة مخفية عن الاستجابات وغير قابلة للإسناد الجماعي. التغيير يتطلب مهاجرة جديدة بعمليتي up/down.
- **SEC-02:** التحقق من ملكية الفروع والأدوار للمستأجر والحارس web؛ إسناد الدور يمر بسياسة UserPolicy، ولا يُمنح دور المالك إلا من مالك، ولا تمنح صلاحيات لا يمتلكها المفوض. تعديل أو حذف حساب المنصة أو المالك أو حساب ذي صلاحيات أعلى محمي بالخادم. إنشاء الأدوار وتعديل صلاحياتها يمنع أسماء النظام والصلاحيات غير المعتمدة أو غير المملوكة. مسار إسناد أدوار الموظف يمر بالسياسة نفسها. إنشاء وتعديل الحسابات والأدوار داخل معاملات.
- **DATA-01:** تسلسل JSON صارم، وفحص ضغط النسخة، وفحص نتيجة الكتابة ووجود الملف وحجمه وبصمة بايتاته قبل تسجيل completed؛ الفشل يرمي استثناء ويسجل failed، فيتوقف مسار الحذف النهائي. لا تدعي هذه الدفعة شمول النسخة لكل الجداول أو وجود تدفق استعادة؛ تلك فجوة مستقلة.
- **SEC-03:** الفواتير PDF والإيصالات الجديدة تحفظ على local الخاص. روابط PDF تعود لمسار إدارة النظام المفوض مع دعم المعاينة والتنزيل؛ إيصالات المستأجر عبر فحص الملكية وصلاحية إدارة الشركة، وإيصالات المنصة عبر صلاحيتها القائمة. عُدلت مرفقات رسائل الفواتير والتحصيل لتقرأ القرص الخاص. الواجهات تستخدم روابط مفوضة بدلاً من بناء روابط storage العامة.
- تسجيل أحداث الدعوات وإدارة الحسابات والأدوار عبر logActivity على User في السجل المنظم، دون كلمات مرور أو رموز أو بصماتها. هذا ليس محرك تدقيق جديداً ولا ضماناً لسجل غير قابل للتغيير.

## التعامل مع الملفات القديمة

الأمر `billing:privatize-documents` يستعرض افتراضياً ولا يغير الملفات. عند --apply يقتصر على invoices/subscription وbank-transfer-receipts، وينسخ إلى التخزين الخاص ويتحقق من SHA-256 قبل إزالة الأصل العام. اختلاف نسخة خاصة موجودة يوقف الأمر دون الكتابة فوقها أو حذف الأصل. إعادة تشغيله آمنة للملفات المنقولة. لا يحدث نقل تلقائي أثناء طلب المستخدم.

حتى تطبيق الأمر، ملفات public القديمة **تبقى مكشوفة عبر روابطها القديمة**؛ لذلك لا يعتبر SEC-03 مغلقاً تشغيلياً بمجرد نشر الكود. مسار تنزيل الإيصالات المفوض يدعم القراءة المؤقتة من public للتوافق إلى حين النقل. تُراجع أيضاً أي نسخ CDN أو object storage وإبطال كاشها ضمن النشر الفعلي؛ لم نفحص البنية التشغيلية هنا.

## ترتيب النشر

1. تنفيذ نسخة مستقلة موثوقة من قاعدة البيانات والتخزين، وتجربة التغيير في بيئة معزولة.
2. تطبيق المهاجرة الجديدة ضمن نشر منسق قبل تشغيل الكود الذي يعتمد الحقول الجديدة:
   `php artisan migrate --force`
3. **إعادة إرسال دعوات الموظفين غير المستخدمة:** الروابط السابقة لا تحمل الرمز الجديد وترفض بعد التحديث. لا تُعد إرسالها تلقائياً لكل المستخدمين، ولا تعيد تنشيط المعطلين. استخدم مسار الدعوة الإداري المعتمد للحسابات المقصودة فقط.
4. معاينة الملفات: `php artisan billing:privatize-documents`.
5. في نافذة صيانة توقف التوليد والرفع مؤقتاً، وبعد مراجعة المعاينة: `php artisan billing:privatize-documents --apply`. راجع أي تعارض يتوقف عنده الأمر بدلاً من تجاوز التحقق. تحقق من عدم بقاء ملفات حساسة عامة ومن اكتمال التنزيل والمرفقات.
6. بناء الأصول وتنظيف الكاش وإعادة تشغيل العمال وفق إجراء النشر المعتمد.

لم تنفذ خطوات النشر أعلاه في قاعدة العمل أو تخزين العملاء. التراجع عن أعمدة الدعوة لا يعيد الروابط القديمة صالحـة، ولا ينبغي إعادة نشر الكود الضعيف أو نقل المستندات الخاصة إلى public للتراجع؛ يعالج التعثر بإصلاح أمامي وخطة تشغيل موثقة.
