# الدفعة الثالثة — المراقبة وبوابات الجودة وقرارات عروض الأسعار

التنفيذ محلي. لا نشر، ولا تعديل لبيانات الفترات القديمة، ولا تشغيل مهاجرات على قاعدة العمل.

## ما تغير

1. فحص الجاهزية: إصلاح اسم دالة معالجة الخطأ، وإرجاع 503 وحالة degraded عند فشل قاعدة البيانات أو الكاش أو الطابور. لا تعرض الاستجابة تفاصيل الاتصال أو نص الاستثناء، وتحتفظ بترويسة التتبع. يسجل التنبيه فئة الاستثناء فقط. فحص الحياة مستقل عن جاهزية التبعيات.
2. فحص عزل المستأجر: إصلاح فقدان عداد الأخطاء داخل الحلقة، وإرجاع exit 1 عند المخالفة وexit 2 عند غياب مجلد النماذج أو عدم فحص أي نموذج. اختُبر السكربت في مجلد مصطنع: نموذج بلا Trait يفشل، ونموذج scoped ينجح. الفحص الحالي استدلال نصي مساعد؛ لا يغني عن اختبارات التفويض والعزل ولا يثبت خلو جميع الاستعلامات من التسرب.
3. فحص الأنواع: إزالة إخفاء الفشل من package.json ومن مسار CI، وإصلاح ستة مواضع وصول غير مضمون في اختبارات الواجهة باستخدام عناصر مطلوبة أو فحص صريح. لم تُخفف strict أو noUncheckedIndexedAccess ولم تُستبعد ملفات من فحص الأنواع. الفحص الحقيقي واختبارات الواجهة ناجحة.
4. PHPStan: إزالة الاستثناءات الخاصة بخدمة محذوفة، وتحويل مسارات الاستثناءات من مسارات جهاز مطلقة إلى مسارات المشروع النسبية. أزيلت كذلك استثناءات قديمة غير مطابقة أو ذات عدادات خاطئة بدلاً من توسيعها لإخفاء الملاحظات. عاد التحليل إلى فحص المصدر فعلياً. نجاح تشغيل المحلل لا يعني نظافة الكود: بقيت ملاحظات مصدر متراكمة، والبوابة تبقى حمراء لها؛ لم تُنشأ baseline جديدة تشملها ولم يُعطل الفشل. تفاصيل النتيجة النهائية محفوظة مع الأدلة.
5. قرارات عروض الأسعار: الموافقة والرفض في مساري المشاركة والموظف داخل معاملات مع قفل وإعادة قراءة الحالة. القرار النهائي لا يقبل استبداله بطلب لاحق، والمنتهي لا يقبل القرار، والمحذوف لا يُعرض أو يُعتمد عبر الرابط العام. أضيف logActivity على العرض مع الهوية والنطاق والقناة والحالة والقيمة، وترجمت رسائل القرار والإشعارات. لا تسجل صورة التوقيع أو نص سبب الرفض في السجل. تحويل العرض يعيد فحص الاعتماد والتحويل تحت القفل أيضاً، لمنع نسختين قديمتين من إنشاء كرتين.

## نوع سجل القرارات وحدوده

السجل هو سجل منظم عبر آلية Log القائمة، على غرار سجل المستخدم والفاتورة. لا يدعي هذا التغيير إنشاء دفتر قرارات مستقل غير قابل للتغيير أو توقيع قانوني غير قابل للإنكار. مدة الاحتفاظ وحماية ملفات السجل وإرسالها لمنصة المراقبة مسؤولية إعداد النشر. لم يُنشأ محرك تدقيق موازٍ.

## مراجعة الفترات السابقة دون تغييرها

أضيف الأمر التالي، ويُلزم تحديد المستأجر:

```bash
php artisan tax-periods:review-legacy TENANT_ID
```

يُرجع JSON يحدد أنه للقراءة فقط، وعدد فترات الفروع السابقة، ومعرف الفترة والفرع والمفتاح والحالة وعدد المعاملات. لا يحذف ولا يدمج ولا يغير حالة أي سجل، ولا يخرج أسماء العملاء أو مبالغهم. اختُبر فصل مستأجرين وثبات سجلات الفترة بعد تشغيله.

أُجريت أيضاً قراءة تجميعية محدودة من قاعدة العمل، دون إظهار معرفات أو بيانات العملاء: **فترة فرع سابقة واحدة بحالة posted، تخص مستأجراً واحداً، وصفر مجموعات فترات مكررة بالمفتاح نفسه**. هذا ليس دليلاً على صحة الإقرار السابق أو شموله لكل الفروع. يلزم للمراجعة المالية مقارنة تسجيل المنشأة ونطاق الفترة ومستندات الفروع وإثبات الترحيل السابق قبل أي تسوية؛ لا نعيد ترحيلها أو دمجها آلياً.
