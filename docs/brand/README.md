## 1. الشعار المعتمد — «الترس والسهم»

ترس مسنّن يمرّ من داخله سهم صاعد ينبثق بين أسنانه.

**المعنى:** التقدّم في قلب الآلة — محرّك الورشة (الترس) هو ما ينفّذ العمل، والسهم الصاعد هو ما ينتجه: خدمة أسرع، وأرباح أعلى، ورقابة تتصاعد.

**لماذا هذا المفهوم:** النظام ليس ورشة واحدة بل منصّة ERP تدير ورشاً ومستودعات وموارد بشرية وفوترة. الشعار «الترس والسهم» يحمل إشارة الصيانة الميكانيكية — وهي أقوى إشارة تملكها المنصّة — ويقرأ بوضوح حتى عند **16px**.

### البدائل التي استُكشفت ولم تُعتمد

| المفهوم | الفكرة | سبب عدم الاعتماد |
| :--- | :--- | :--- |
| `link` | سلسلتان متشابكتان | أنيق لكنه مجرّد؛ لا يحمل إشارة الورشة، ويضيع عند الأحجام الصغيرة |
| `key` | مفتاح بمقبض ترس ينتهي بسهم | قريب جداً من الشعار السابق، ويذوب عند 16px |
| `monogram` | حرف K بذراع على شكل سهم | واضح جداً لكنه مشروع مؤسسي عام بلا إشارة ميكانيكية |

نسخة كل مفهوم (SVG + PNG) محفوظة في [`docs/brand/concepts/`](concepts/) كمرجع بصري، مع لوحة المقارنة [`sheet.png`](concepts/sheet.png).

## 2. الملفات المولّدة

| الملف | الوصف | الاستخدام |
| :--- | :--- | :--- |
| `logo.svg` | البلاطة على-shell كحلي | الأيقونة الأساسية: الشريط الجانبي، تسجيل الدخول |
| `logo-blue.svg` | البلاطة على-shell أزرق العلامة | خلفية فاتحة، بطاقات، مواد تسويقية |
| `logo-mark.svg` | العلامة وحدها، `viewBox` مضغوط على الرسم | الترويسة، image tag، طباعة |
| `logo-mono.svg` | العلامة بلون واحد (`currentColor`) | طباعة، أو أي سياق يفرض لوناً واحداً، أو إدراج SVG داخل HTML |
| `logo-{16..1024}.png` | البلاطة بكل المقاسات | `app_logo` الافتراضي، favicons |
| `logo-blue-{32..1024}.png` | البلاطة الزرقاء | بديل تسويقي |
| `logo-mark-{256,512}.png` | العلامة على خلفية شفافة | Open Graph |
| `favicon.{ico,png}` · `apple-touch-icon.png` | أيقونات المتصفح | `resources/views/app.blade.php` |

**إعادة التوليد:**

```bash
npm run brand          # SVG + كل PNG + favicon + landing/webp + og-image
npm run og:image       # بطاقة المشاركة العامة (landing)
```

`npm run brand` يجب أن يُشغَّل بعد أي تعديل على `scripts/build-brandmark.mjs`.

## 2.1 التركيب في النظام الحيّ — ما الذي يتجاوز المولّد

`npm run brand` ينتج ملفات `public/images/brand/` فقط. لكن **الشعار الذي يراه المستخدم فعلياً** يأتي من إعدادات قاعدة البيانات، وهذه طبقة منفصلة عن المولّد:

| الإعداد | أين يُقرأ | البديل الافتراضي |
| :--- | :--- | :--- |
| `system.brand_logo` | `HandleInertiaRequests.php` → `app_logo` | `images/brand/logo-256.png` |
| `system.brand_favicon` | `HandleInertiaRequests.php` → `app_favicon` | `images/brand/favicon-32.png` |
| `website.logo` | ترويسة الصفحة العامة | — |
| `website.favicon` | الصفحة العامة | — |
| `tenants.logo_path` | الشعار الجانبي داخل التطبيق | `images/brand/logo-256.png` |

> **قاعدة:** الشعار الذي يظهر في تسجيل الدخول والشريط الجانبي هو `app_logo`، أي **الملف المرفوع** لا الملف في `public/`. لو غيّرت المولّد وحده، سيبقى المستخدم يرى الشعار القديم.

**عند تبديل الشعار** يجب أيضاً تحديث الملفات المرفوعة (نفس المسارات، محتوى جديد):

```
storage/app/public/brand/<brand_logo>.png    ← public/images/brand/logo-512.png
storage/app/public/brand/<brand_favicon>.png ← public/images/brand/logo-64.png
storage/app/public/website/<website.logo>.png   ← public/images/brand/logo-512.png
storage/app/public/website/<website.favicon>.png ← public/images/brand/logo-64.png
storage/app/public/tenants/<id>/<tenant logo>.png ← public/images/brand/logo-512.png
```

(أُعيد تحديث هذه الملفات عند اعتماد الشعار الحالي، بتاريخ 2026-11-15. النسخ القديمة محفوظة في `/tmp/khidmah-old-brand/` — وهي مؤقتة على قرص النظام، لا تعتمد عليها.)

**مهم:** هذا التحديث يطمس أي شعار رفعه مدير النظام. من يريد استبداله لاحقاً يستخدم شاشة **الإعدادات ← عام** لرفع شعار جديد.

## 4. القيود الهندسية — لا تُكسر

هذه القيم ليست ذوقاً؛ هي ما يمنع تشوّه الشعار. أي تعديل يجب أن يُراجَع بصرياً بعد التوليد.

| المعامل | القيمة | السبب |
| :--- | :--- | :--- |
| عدد أسنان الترس | `8` | مع `phase 22.5` يضع **سناً واحداً على كل جانب** من السهم |
| طور الترس | `22.5°` | أي طور آخر يضع سنّاً **تحت رأس السهم**، فيقصّ الهالة (`halo`) طرفه ويترك **شظيّة ذهبية منفصلة** بجانب السهم |
| نصف عرض رأس السهم | `50` | عرض الرأس 100px، والفجوة بين طرفي السنّين ~116px. رأس أعرض يلامس الأسنان، وأضيق يبدو ضعيفاً أمام الترس |
| هالة القطع | `10` | قناة الفصل حول السهم داخل الترس. بدونها يندمج السهم بالترس وتضيع حدوده |
| نصف عرض ساق السهم | `30` | يتوقف عند `y=312` **داخل** الثقب (`rHole=62`) فوق قاعه — فيقرأ السهم صاعداً **عبر** الترس لا محبوساً فيه |
| نصف قطر الثقب | `62` | يبقى ثقباً دائرياً نظيفاً عند كل حجم |

**القاعدة:** أي تعديل على هذه المعاملات يمرّ بعرض الشعار على ورقة المقارنة (`docs/brand/concepts/sheet.png` methodology) وعلى الأحجام 16/32/64/128 قبل الاعتماد.

## 5. قواعد الاستخدام

مستوحاة من `.agents/skills/brand/references/logo-usage-rules.md`:

- **المساحة الآمنة** = ارتفاع العلامة على كل الجهات.
- **الحد الأدنى:** البلاطة `24px` (واجهة) · `16px` (favicon) · العلامة وحدها `32px`.
- **الخلفية:** البلاطة الكحلية على الفاتح أو الغامق · البلاطة الزرقاء على الفاتح · العلامة الذهبية وحدها على الغامق.
- **ممنوع:** تمطيط، تدوير، إضافة ظلال، قصّ أجزاء، ألوان خارج اللوحة، تغيير التدرّج.
- **على الفاتح** استخدم `logo.svg` أو `logo-blue.svg` (البلاطة)، ولا تستخدم `logo-mark.svg` الذهبي وحده — الذهبي الفاتح على الأبيض يفقد تباينه.

## 7. بند مفتوح — صورة الـ hero في الصفحة العامة

`public/images/landing/FXHzyVlYFrkltsYphSMwQJs5tN5b5RjkAvAQw1wo.{webp,avif}` هي **mockup تسويقي مُعدّ يدوياً** (مجموعة لقطات من واجهات التطبيق) ولا يوجد له مولّد سكربت.

الحالة الراهنة: هذه الصورة ما زالت تعرض **الشعار القديم** (حرف K أرجواني مع ترس)، لأن لقطاتها أُخذت قبل اعتماد الشعار الحالي.

**لماذا لم تُحدَّث تلقائياً:** إعادة بنائها ليست مهمة توليد أصول — هي قرار تصميمي على التكوين البصري (أي شاشات، أي ترتيب، أي إطار). وتحديثها بلا قرار من المطوّل قد ينتج مادة تسويقية أسوأ من الحالية.

**الخيارات:**
1. تُعاد بناؤها يدوياً/بمولّد مؤقت مع الشعار الجديد — يحتاج اعتماد على التكوين.
2. تُزال من الـ hero واستُبدلت بلقطة حقيقية من التطبيق الحالي تُلتقط آلياً (مؤقت إلى الأبد، وتبقى صادقة).

حتى يُقرَّر أحدهما، صورة الـ hero هي **السطح الوحيد** الذي لا يزال يعرض الشعار القديم.
